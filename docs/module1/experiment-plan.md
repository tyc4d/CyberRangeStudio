# 模組 1 小型實驗計畫（Lead 整合版，2026-11-14）

來源：`experiment-plan-claude.md`、`experiment-plan-codex.md`（兩個 Worker 各自獨立擬定）。
狀態：**提案，等產品負責人核准。尚未執行，沒有呼叫過任何 LLM。**

## 目的

用少量真實報告，量出「分段處理」是否真的比「一次問完」好、好多少、值不值得多花的工。
不預設分段處理會贏。

## 模組 1 最少的輸入與輸出

- **輸入**：一份已是文字的英文報告，程式先切段編號。（STIX 這一輪不測）
- **輸出**：
  - 攻擊行為清單：做了什麼、對什麼目標、用什麼工具或指令，附段落編號與原句。
  - 每一項標明：**報告明講／推測／報告沒寫**。
  - 行為之間的關係，**時間先後**與**依賴**分開填，預設「不明」，推測要寫理由。
  - 目標環境與工具痕跡（系統、版本、漏洞編號、指令），各附出處。
  - 缺少項目，以及可計算的檢查數字（不給單一總分）。

## 三種錯誤怎麼防、怎麼驗

| 錯誤 | 防法 | 實驗怎麼驗 |
|---|---|---|
| 漏掉行為 | 逐段標記有無攻擊行為；標了有卻沒抽出的段落列警示 | 和人工答案比找到幾成 |
| 編造資訊 | 程式核對原句存在；編號、版本、IP、指令必須在原文逐字出現；禁用報告以外的知識 | 人工判斷原句是否真的支持；**刪段測試**（拿掉某段重跑，該項應消失） |
| 關係判錯 | 時間與依賴分兩欄；敘述順序不自動當時間順序；綜合多起事件的報告不硬串成一條線 | 答案也分兩欄標；專看「把先後說成依賴」「把不明硬排順序」 |

## 資料：6 份考題＋1 份調校用

- 現有 3 份（CISA Volt Typhoon、Microsoft Midnight Blizzard、Mandiant Ivanti）。
- 2 份取自 MITRE Attack Flow 中「單一事件、單一來源、原文仍可取得」的案例。
- 1 份發表時間晚於模型訓練截止日的報告，看「沒背過」時的表現。
- 另 1 份只用來調整提示，不計分。

**Attack Flow 的定位**（本機 `~/attack-flow/corpus`，41 個人工流程）：
可表達步驟、順序、條件分支；用作第三方對照，檢查我們的答案有沒有漏。
不直接當標準答案：節點沒標出自原文哪一段、連線不分先後與依賴、多為單一作者未見複核。

## 比較的做法（同一模型、同一輸出格式）

- 甲 一次問完（基準線）
- 乙 分段處理：先抽行為，再判關係，再抽環境與工具
- 丙 分段＋複查：乙之後再逐項對照原文檢查並找漏項

每份報告、每種做法各跑 3 次，共 54 次。刪段測試只對勝出的做法做。

## 參考答案怎麼做才可信

1. 先寫標註規則（行為切多細、什麼算明講、什麼算依賴），用它重整現有 25 項／21 條。
2. 兩人各自只看原文標註，不看 LLM 輸出、不看 Attack Flow。
3. 比對、記錄一致比例，不一致處討論定案並留理由。
4. 再用 Attack Flow 對照補漏。
5. 評審看不到結果是哪種做法產生的。不用 LLM 當裁判。

## 成功門檻（提案）

可信度（任一不過就不算成功）：

| 指標 | 門檻 | 誰來量 |
|---|---|---|
| 原文沒有的編號、版本、IP、指令 | 0 個 | 程式 |
| 引用的原句確實存在 | ≥ 98% | 程式 |
| 標成「明講」卻沒有原文支持 | ≤ 5% | 人工 |
| 把推測標成明講 | ≤ 5% | 人工 |
| 說有依賴的，確實是依賴 | ≥ 85% | 人工 |
| 把先後說成依賴、把不明硬排順序 | ≤ 10% | 人工 |

完整度（可略低，後面有模組 2 與人工確認補）：

| 指標 | 門檻 | 誰來量 |
|---|---|---|
| 行為找到率 | 整體 ≥ 80%，單份 ≥ 65% | 人工 |
| 依賴關係找到率 | ≥ 60% | 人工 |
| 報告沒寫的項目正確列為缺少 | ≥ 80% | 人工 |
| 同一份跑 3 次，行為清單重疊 | ≥ 80% | 人工 |
| 每份報告費用與時間 | ≤ 2 美元、≤ 10 分鐘 | 程式 |

選「通過全部門檻中最簡單的做法」。乙若沒有比甲多找到 10 個百分點、或編造沒有少一半，
就不值得做複雜流程。

Codex 提的門檻較嚴（找到率 ≥ 85%、無根據事實 ≤ 2%）。Lead 採較寬的版本作為第一輪，
理由：樣本只有約 60 個行為，一項就差 1～2 個百分點，太嚴的門檻量不準。

## 成本

- LLM 費用：兩個 Worker 估計差很多（Codex 2～5 美元、Claude 20～40 美元），
  差異來自假設的模型單價。**建議設上限 50 美元**，執行前依實際牌價重估。
- 人力才是主要成本：標註約 20 小時（兩人合計）、評審約 15～20 小時。

## 這個實驗不能證明什麼

- 只測 6 份公開英文報告。中文、掃描檔、STIX、只有 IOC 的情資都沒測。
- 不能完全排除 LLM「背過」這些事件。
- 答案是人的解讀；兩人一致不代表報告本身寫得對或寫得全。
- 「依賴」只驗到「報告這樣說」，真假要到實際環境重現（模組 8）才知道。
- 不能證明輸出足以建環境，因為後面模組需要哪些欄位還沒定。

## 需要產品負責人決定

1. 第二位標註者是誰（需有情資分析背景）？沒有的話，所有數字只能算「暫定」。
2. 是否接受「寧可漏、不可錯」的門檻取捨。
3. 是否核准執行：LLM 費用上限 50 美元、人力約 40 小時；需要寫一次性的實驗腳本（非產品程式）。

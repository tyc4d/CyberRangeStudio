# 模組 1「情資報告分析」小型實驗計畫

狀態：設計提案，尚未核准開發。目標是比較分析方法，不預設產品架構。

## 1. 最少輸入與輸出

- 輸入至少有可讀的情資內容，以及可回到原文的頁碼、段落或 STIX 欄位位置；保留原檔、版本與解析警告。
- 可接受的來源形式是 CTI 報告文字、STIX 1.x XML 或 STIX 2.x JSON；格式解析錯誤要明示。只有 IOC 的 STIX 不足以支持攻擊流程，不得補寫步驟。
- 每項輸出包含：事件基本資料、原子攻擊行為、目標環境、工具／IOC／指令、關係、缺少項目及來源證據。
- 每項主張標成「明載事實、推論、未知」之一，附來源位置與原句；關係另標「時間先後」或「依賴（前一步是後一步的必要條件）」，不明就保留未知。
- 輸出另含可讀 JSON、解析警告及分項品質數字。缺少項目只能依暫定清單計算；正式清單需待下游需求確認。

## 2. 防漏、防編造、防錯判關係

- 把攻擊行為當成事件中的具體行動逐項抽取；ATT&CK 技術標籤不能代替行動清單。保留分支、多事件和來源中的不確定語氣，不硬湊成單一路徑。
- 每項主張都要附精確引文與頁／段／欄位位置。程式檢查位置及引文是否存在；人工判斷原文是否真的支持主張。只找到引用不算驗證通過。
- 本輪只准依輸入內容作答；來源沒寫、模糊或互相矛盾就標未知／推論／衝突，不用模型記憶補版本、受害主機或指令。
- 時間上先發生不等於後續行動依賴它。兩種邊分開標註與計分；一般 `related-to` 不視為任何一種邊。沒有明確依據時不連邊。

## 3. 小樣本比較與參考答案

- 使用既有三份真實報告：CISA Volt Typhoon、Microsoft Midnight Blizzard、Mandiant UNC5221／Ivanti；沿用已準備的原文、定位資料與 25 個行為／21 條邊暫定清單。再選三份未在前期題庫、近期或較少被討論且型態不同的公開報告，避免六份全是知名單一事件。
- 既有清單只作起點：目前只有一人整理、粒度尚有爭議，未經第二位分析師複核；先重審並鎖定答案，再看模型輸出。
- 比較兩法：甲、整份報告一次抽出所有欄位；乙、依有定位的段落分段抽原子主張，合併後再獨立判關係。可沿用既有評量腳本中適用的部分，但先核對它是否支援這兩種輸出；不把未送出的舊模型測試當結果。相同模型、提示、輸出規格與每份報告費用上限；記錄所有請求、版本、用量與失敗。
- 兩位 CTI 分析師先各自通讀每份原文，標出行為、證據、明載／推論／未知，以及時間邊和依賴邊；對分歧逐項協議並留理由，無法裁定的項目標模糊、不計作確定答案。不得用 LLM 裁判。
- `/home/tyc4d/attack-flow/corpus/` 的人工編寫真實事件流程可作輔助參照：Attack Flow 能表達步驟與順序，也能提示分支及關係核查。只在事件和來源相符時，回查原始報告逐項確認；流程有來源連結不代表每個節點都受該來源支持，也不代表完整或無爭議，不能單獨當標準答案。
- 每份報告、每種方法各跑 3 次，共 36 次端到端處理；乙可能包含多次模型呼叫，全部計入費用。粗估約 US$2–5，先設 US$10 總上限；正式執行前按當時價格與輸入長度重新估算。既有研究沒有真正呼叫過 LLM，這只是預算估計。

## 4. 成功門檻與量法

- 輸出格式與必填欄位檢查：有效率 100%，自動檢查。
- 攻擊行為：精確率至少 90%、召回率至少 85%；逐項與人工裁定答案比對，人工確認是否同一行為。
- 引文：位置和原句吻合率 100%，自動檢查；引文支持主張比例至少 95%，由分析師判斷。
- 無根據的「明載事實」不超過全部事實主張的 2%，且不得有未支持的高影響行動、目標版本或指令；人工逐項判斷。推論必須明標，不能計成事實。
- 關係分開計分：時間邊精確率與召回率各至少 80%；依賴邊精確率至少 90%、召回率至少 70%。比對人工裁定答案，人工判斷方向和關係類別；模糊邊另列、不硬算成正解。
- 同報告三次輸出的行為集合平均重合率至少 80%（兩次清單交集除以聯集）；依人工確認後的同一行為計算。指標按報告列出，不只報平均，並附樣本數。
- 若兩種方法都未達門檻，或只靠錯標推論／錯連依賴才達標，第一版不應宣稱可自動分析。

## 5. 不能證明的事

- 六份公開報告不能證明可泛化到所有威脅、語言、掃描檔、圖片或真實 STIX 1.x／2.x 輸入；本輪主要量報告文字分析。
- 報告可能省略真實步驟或因果，參考答案也會受分析師判讀影響；無法證明重建出真實完整時間線或因果關係。
- Attack Flow 是有價值的人工參考，不是事件真相的完整金標；格式能表示流程不等於某個流程標註正確。
- 達到門檻不代表輸出可免人工審查，也不證明後續場景能部署、重現或驗證成功。
